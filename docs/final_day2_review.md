## 선택 과정·구현 검토

`src/train_day2.py`의 select/evaluate 분리와 저장된 계획·선택 고정·평가 기록을 대조했다.

- 계획 생성 → CV 결과 → 선택 고정 → 최종 평가 순서의 시각과 해시가 일치했다. 입력 데이터, 분할, 학습 코드, 계획, CV 결과, 고정 모델 파일의 해시가 기록과 일치했다.
- 후보는113개, CV fit은339개, 특성 집합은8개다. 후보 선택은 GroupKFold3개 검증 MAPE의 단순 평균을 최소화했다.
- 개발28개/18개 프로토콜을 fold18/10,19/9,19/9로 나눈다. 각 fold의 train/valid 셀과 정확한 프로토콜 문자열 중복은0이다.
- 기록된339개 fold의 중앙값 대치 통계 및 필요한 표준화 평균을 해당 fold 훈련 셀에서 재계산해 일치를 확인했다. 113개 후보의 OOF 예측으로 CV MAPE 평균과 표본SD를 다시 계산해 일치를 확인했다.
- C037이 CV 최소 후보이다. no_qd_change7, Ridge(alpha=10), ln타깃/exp복원이며 지표는 원래 사이클 단위로 계산한다.
- 전체 모델과 계열별4개 후보는 holdout/B2 평가 전에 고정됐다. B2에서 Linear C104가28.57%로 더 낮아도 최종 모델을 교체하지 않았다. 계열별 최종 결과와 선택 결과를 구별한다.
- 최종 파이프라인은 개발28개로만 fit하고 같은 모델로 holdout/B2를 예측한다. holdout을 합친36개 재학습, 테스트 기반 클리핑·보정·재선택이 없다.
- random KFold 민감도10.05±2.52%는 별도 진단이며 선택 근거로 쓰지 않았다. 그 fold별4/3/5개 프로토콜 중복과 기존 holdout5/8개의 개발 프로토콜 공유를 공개했다.
- 단일특성·IR제외·중복제외·Delta Q 대체 비교의 값은 고정된 Ridge/ln타깃/alpha10/동일fold 행과 일치한다. 이 대조를 외부 배치 성능 개선의 확정 증거로 표현하지 않는다.

저장된 `validation.json`은 초기100사이클 이내 특성 재계산, 네 고정 모델의188개 최종예측 재현, 선택/출력 무결성 검증도 통과했다고 기록한다. 이번 보고서 검토에서는 모델을 새로 학습하지 않고, 해당 기록·소스와 선택 모델 지표 등을 독립적으로 대조했다.

## 실패 해석의 적정성

최대APE5셀, 모든 단수명28셀의 과대예측, B2 30/39개의 학습 타깃 최솟값 미만, 초기 용량23/39개·기울기21/39개·log분산18/39개의 학습 범위 이탈은 저장 예측·처리 데이터와 일치한다. 기울기21개는 위쪽20개와 아래쪽1개를 합친 수다.

IR 결측6개44.35%/비결측33개57.19%, 알려진 프로토콜7개69.44%/미지32개52.11%라는 반례를 제시해 결측 또는 미지 프로토콜 하나를 원인으로 확정하지 않는다. newstructure 미표기30개와 학습 최소수명 미만30개의 중첩, B1근사/B2관측 라벨과 배치의 중첩을 공개했다. 배치·수명 범위·측정 조건·라벨의 효과를 현재 자료로 분리하지 못한다는 해석이 적절하다.

소표본, 후보 선택 편향, B2분포를 이미 관찰한 EDA, 불완전 기록 제외, 라벨 품질, 프로토콜 일부 중복과 논문 비교 조건 차이를 설명한다. 현장 검증 전 교체·충전제어·안전 판단 자동화에 사용하지 않으며 실험 셀 사이클 수를 ESS팩의 달력 수명으로 직접 번역하지 않는다.

## 수업 내용 기반 여부

`course_alignment_review.md`에 기록한 Statistics·MLDL·Wrap-up·Evaluation Metrics·ML Hyperparameters·녹음 지시와 현재 산출물의 적용을 대조했다.

- 분석 단위/X/Y, 결측·이상치·분포·상관·로그변환은 문제 정의와 피처/오류 분석에 이어진다.
- 선형회귀·Ridge·Random Forest·규제·다중공선성·교차검증은 후보와 특성 대조에 반영됐다.
- 훈련 부분에서만 전처리fit, 미래 정보 제외, 평가셋으로 최적화하지 않는 원칙을 코드와 기록에서 확인했다.
- 목적에 따른 회귀 지표와 과적합/일반화 차이 해석을 보고했다.
- GroupKFold·Pipeline·TransformedTargetRegressor는 이 원칙을 구현하기 위한 확장 도구다. 수업 또는 노션이 해당 API나 모든 하이퍼파라미터를 의무화했다고 주장하지 않는다.
